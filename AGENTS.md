# Правила работы агента в репозитории (ICT — Технологии промышленной чистоты)

Эти правила являются обязательными для любого ИИ-агента, работающего с данным проектом.

## 1. Минимальные и точечные изменения (только по существу)
- Изменять код **строго по существу поставленной задачи**.
- Не вносить «попутных» правок: запрещено без прямого запроса переформатировать файлы, переименовывать переменные/классы, менять порядок CSS-правил, оптимизировать или рефакторить несвязанные участки кода.
- Перед правкой определять минимальный набор строк/блоков, который действительно нужно изменить.

## 2. Неприкосновенность рабочего кода
- **Не трогать рабочий код** при внесении правок в другие секции или модули.
- Если задача касается конкретного блока (например, одной секции лендинга, модального окна или вкладки админки), остальные файлы и функции должны оставаться без изменений.
- Не удалять и не ломать существующие режимы работы админки (GitHub API, PHP-обработчики, локальный режим) и конвертацию в WebP.

## 3. Сохранность структуры и контрактов данных
- Данные сайта хранятся в JSON-файлах и не должны зашиваться обратно в HTML без необходимости:
  - `data/site-config.json` — контакты, гарантии, реквизиты.
  - `data/media.json` — пути к WebP-изображениям (Hero и пары «До/После»).
  - `data/services.json` — перечень услуг, списки «Что входит» / «Что не входит» и таблица дополнительных работ с ценами.
- Все загружаемые фотографии должны храниться в формате `.webp` в `assets/images/`.

## 4. Безопасность
- **Категорически запрещено** сохранять GitHub-токены (`ghp_...`, `github_pat_...`), пароли, хеши боевых паролей и любые другие секреты в отслеживаемых Git-файлах, комментариях или конфигах репозитория.
- Локальные секреты для PHP-хостинга размещать только в `admin/api/config.local.php` (файл добавлен в `.gitignore`).
